## Выполнение задания

### 1. Вероятности вместо готовых классов

Вместо обычного:

```python
model.predict(X)
```

используются вероятности положительного класса:

```python
proba = model.predict_proba(X)[:, 1]
```

После этого класс определяется вручную:

```text
prediction = 1, если probability >= threshold
```

Стандартный порог большинства бинарных моделей равен `0.5`, но он не обязан быть оптимальным для конкретной задачи.

### 2. ROC-кривая

Построена ROC-кривая, которая показывает компромисс между:

- True Positive Rate (Recall);
- False Positive Rate.

Также рассчитан ROC AUC.

На test:

```text
ROC AUC ≈ 0.9160
```

Высокий ROC AUC означает, что модель хорошо ранжирует положительные объекты выше отрицательных, независимо от конкретного порога.

### 3. Precision-Recall анализ

Построена PR-кривая и рассчитан Average Precision.

PR-кривая особенно полезна, когда положительный класс важнее или классы распределены неравномерно, потому что напрямую показывает компромисс между Precision и Recall.

### 4. Перебор порогов

Проверены пороги:

```text
0.01 ... 0.99
```

Для каждого вычисляются:

- Accuracy;
- Precision;
- Recall;
- F1-score;
- FP;
- FN;
- бизнес-стоимость ошибок.

### 5. Стоимость ошибок

Использована функция:

```text
Cost = FP × cost_fp + FN × cost_fn
```

В эксперименте:

```text
cost_fp = 1
cost_fn = 10
```

То есть пропустить положительный объект в 10 раз хуже, чем ошибочно пометить отрицательный как положительный.

### 6. Выбор порога только на validation

Порог выбирается по validation-выборке, а не по test.

Это важно, потому что если подбирать порог непосредственно по test, test перестаёт быть независимой оценкой качества и возникает утечка информации в процесс настройки.

По validation выбран:

```text
threshold = 0.36
```

### 7. Сравнение с порогом 0.5

На test получено:

| Порог | Accuracy | Precision | Recall | F1 | FP | FN | Cost |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0.50 | 0.8333 | 0.8000 | 0.5714 | 0.6667 | 1 | 3 | 31 |
| 0.36 | 0.7917 | 0.6000 | **0.8571** | **0.7059** | 4 | 1 | **14** |

После снижения порога:

- Accuracy немного снизилась;
- Precision снизилась;
- Recall значительно вырос;
- F1 вырос;
- FN уменьшились с 3 до 1;
- стоимость ошибок снизилась с **31 до 14**.

Это и есть причина, почему порог `0.5` нельзя считать универсально лучшим.

---

## Интерпретация результата

Если цена FN намного выше цены FP, модель должна быть более чувствительной к положительному классу. Снижение порога заставляет её чаще предсказывать `1`.

Это приводит к двум последствиям:

- больше истинно положительных объектов обнаруживается;
- одновременно растёт количество ложноположительных срабатываний.

Оптимальный порог определяется не только статистическими метриками, но и реальной стоимостью разных видов ошибок.

---

## Ключевые результаты

- ROC AUC на test ≈ **0.9160**;
- стандартный порог: `0.50`;
- выбранный порог: **`0.36`**;
- Recall: `0.5714 → 0.8571`;
- F1: `0.6667 → 0.7059`;
- FN: `3 → 1`;
- стоимость ошибок: `31 → 14`.

---

## Вывод

Вероятностная модель не обязана использовать порог `0.5`. Порог является отдельным параметром принятия решения и должен соответствовать прикладной задаче. В данном эксперименте FN значительно дороже FP, поэтому уменьшение порога до `0.36` увеличило Recall, уменьшило количество пропущенных положительных объектов и более чем в два раза снизило итоговую стоимость ошибок, несмотря на небольшое снижение Accuracy.
